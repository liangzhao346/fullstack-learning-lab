# 缓存异常对照实验

页面会依次调用原始与保护两组实验，真实读取当前学习数据库。demo 使用本地可过期存储；mysql-redis 模式使用 Redis。故障实验由局部适配器注入读取错误，不会停止 Redis 服务。

| 现象 | 实验触发 | 保护方案 | 看什么 |
| --- | --- | --- | --- |
| 穿透 | 顺序请求同一不存在的 ID | 2 秒空值缓存 | 原始 dbReads 接近请求数，保护后通常一次回源，其余 negativeHits |
| 击穿 | 一个已预热热门 key 过期后并发读取 | 加锁后再次查缓存，合并回源 | 原始同时多次读取，保护后一次填充，其余复用 |
| 雪崩 | 多个 key 在约 400ms 一起过期 | 确定性的 400–1600ms 错峰预热 TTL | seededTtlMs 分布与过期窗口内 dbReads |
| 故障 | 实验缓存读取全部抛错 | 最多 4 个并发回源，超限明确拒绝 | cacheErrors、dbReads、rejected、failedRequests |

实验每次最多 60 次请求、8 个工作线程，同一实例同时只运行一组。35ms 的人工回源延迟与加速 TTL 只为显现差异，不是性能基准或真实容量预测。每次随机 key 前缀，最后只清理自己创建的 keys，没有 FLUSHDB。

## 指标口径

- requests：发起的业务读取次数。
- hits：最后由缓存返回的次数，含等待其他请求填充后的命中。
- misses：第一次读取缓存未命中；同一请求可能先 miss 后在锁内 hit，两者不能简单相加计算请求数。
- dbReads：实验阶段的实际 Repository 回源次数，不含预热和样本列表查询。
- negativeHits：缓存中缺失标记的命中次数。
- cacheErrors：缓存操作异常次数；故障与普通 miss 分开计数。
- rejected：故障时回源并发预算不足的请求数。

## 保护的边界

空值缓存只对相同缺失 key 的重复请求有效；大量不同随机 ID 还需要输入限制、访问限流，必要时使用布隆过滤器。布隆过滤器本项目只作为后续练习，没有伪装成已实现功能。

击穿保护用的是当前 Java 进程内的条带锁，不是分布式锁，多实例要另行设计协调。TTL 抖动只能分散批量计划失效，Redis 整体不可用时仍需有界回源、熔断或降级。此处实现的是有限并发的回源预算，没有把它称为完整分布式熔断系统。

实验结果会受调度与数据量影响，以实际指标为准。修改商品数量、实验请求数或数据后，不要求每次得到完全相同的毫秒数和缓存命中次数。
