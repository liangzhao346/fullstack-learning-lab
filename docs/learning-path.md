# 分阶段学习路线

每次只完成一条能够解释和验证的小链路，不先背整个技术栈。

## 1. 页面与 HTTP

启动项目，在商品页点击「读缓存」。在请求观察窗与浏览器 Network 中找到 GET 地址、200 状态、data、requestId。再手动访问一个不存在的正整数 ID，观察 404。阅读 `client/src/App.vue` 的 api 函数以及 `ApiController`。

练习：说清楚页面没有直接查询数据库，而是在向哪个接口发送什么请求。把非法价格发送给接口，确认后端仍会拒绝。

## 2. Spring Boot 与分层

从 `LabApplication` 读到 `ApiController`、`ProductService`、`ProductRepository`。找到商品列表的参数、分页 SQL、结果转换。为列表增加一个排序方式之前，先画出请求经过的文件。

练习：在独立分支增加一个只读统计接口，定义响应、实现 SQL，再在页面显示它；增加验证后再认为完成。

## 3. 数据库与编辑冲突

阅读 Flyway SQL 和数据库约束。创建商品，在两个页面打开同一版本后分别编辑，第二次旧版本提交应返回 409。对已下单商品执行删除应返回冲突，理解外键为何存在。

练习：用新增迁移给商品增加一个可空备注字段，同步 DTO、SQL、表单和测试。不要直接修改已经运行过的 V1 迁移。

## 4. 事务与幂等

创建库存为 1 的商品，用新 requestKey 尝试下单两次，只有一次能创建。保持同一标识和内容重发，库存不应重复扣减；改变数量后沿用标识应冲突。阅读 OrderTransaction 和对应并发测试，解释为什么单靠页面禁用按钮不够。

## 5. 缓存

先理解一次详情请求：查缓存，未命中查数据库，填充短期缓存。再进入实验室逐个比较穿透、击穿、雪崩和缓存故障，记录实际 dbReads、hits、negativeHits、rejected，而不只比较耗时。

练习：解释短期空值缓存为何不能挡住无限不同的随机 ID；解释 TTL 抖动为何不能解决 Redis 整体宕机。然后准备真实 MySQL/Redis，用相同接口重复观察，不把两种模式混为一谈。

## 后续方向

登录与权限、文件上传、WebSocket、消息队列等可以各自成为后续学习项目。先明确一个新的学习目标，再选择能体现它的业务，不把所有技术一次堆进本项目。
